# R7.4.5 — Fixed Machado tables and bounded indices

## Scope and evidence

The experiment investigates the dynamic table length and result construction in
Machado severity interpolation. No qualified original model, color-d production
source, public API or gamut policy is changed.

Initial source: `ea0af378c458765846bbfc4b21f5aa4cf1d14906`,
[run 36917539554](https://github.com/alex-1974/color-d-research/actions/runs/36917539554).
The three variants build and pass all four compiler jobs. That run exposes a
large DMD 2.111.0 float regression with a fixed table and size_t index; its
104 committed measurement/diagnostic files remain in
[data/r7_4_5/run-36917539554](../data/r7_4_5/run-36917539554/).

The focused index follow-up uses source
`451fe26cf477c6f2967b8e4976de97171663adf3`,
[run 36918173698](https://github.com/alex-1974/color-d-research/actions/runs/36918173698).
All four compiler jobs pass. Its 136 committed files are in
[data/r7_4_5/run-36918173698](../data/r7_4_5/run-36918173698/).
Those records retain every raw round, min/median/max summary, platform metadata,
Debug preflight, binary hash and relevant full D kernel/function disassembly.
Complete binary disassembly and generated sources are additionally CI artifacts
and expire. Exact source, workflow build/run commands and deterministic input
generation remain tracked for replay.

## Source variants and semantic contract

All variants borrow runtime coefficients and use adjacent-table interpolation;
none precomputes severity outputs or changes the published coefficient tables.
The original helpers remain unchanged.

- **Slice:** original matrixAtSeverity accepting a dynamically sized borrowed
  slice, original value-returning interpolation.
- **Fixed:** const ref Matrix3!T[11], the same size_t index and ma.lerp arithmetic.
- **Bounded:** fixed table, replacing only the fixed helper's size_t index
  conversion with int. Valid finite severity in [0,1] produces an index in 0..10,
  so truncation and alpha are equivalent under this precondition.
- **Direct:** fixed table, size_t index and nine direct output-field assignments,
  generated by static foreach/mixin from the original expressions; the void
  helper requests inlining. It changes both result construction and the requested
  inlining boundary, so it is not an isolated test of stores alone.

Each candidate has an attributed noinline lookup batch and lookup+apply batch.
The latter still uses original ma.apply and original RGB value construction.
Prepared Machado application and Brettel/Viénot stay on their original paths as
controls in this workflow. Earlier BV candidates remain available in source.

The fixed-size type rules out short tables; this is a stronger representation
contract than the original slice. Bounds checks remain enabled and @safe,
pure, nothrow and @nogc are retained. The compiler may prove valid fixed-table
indices without a runtime check; no unsafe indexing is introduced.

The severity precondition is preserved as an assertion in the research helpers.
Bounded-index equivalence is qualified for finite severity in [0,1], not for
out-of-contract Release calls with NaN, infinity or negative severity.
Color-channel NaN/Infinity behavior is separately tested at valid severities.
This experiment does not settle a production severity-validation policy.

## Validation and timing

For float and double and all three deficiencies, Debug preflights compare all
nine coefficients of each candidate at 1001 severity values, including 0 and 1,
with the original helper. Color application checks include a finite sample,
out-of-gamut RGB, NaN and positive infinity. Representative CTFE checks use a
local fixed protan table and severities 0, 0.35, 0.65 and 1. Helpers and validation
compile through the required attributes.

Optimized -release binaries now explicitly compare all nine coefficients of the
warmed lookup corpus against the original implementation before timing. All RGB
batch modes, including prepared Machado and lookup+apply, likewise compare every
component. Exception checks remain active independently of assertions.
Finite component tolerances remain float 2e-6 / double 1e-12; edge checks preserve
NaN classification and infinity equality, not payloads or signed-zero bits.
The generated finite corpus is checked in optimized mode; edge probes are Debug.

All twelve initial-run and sixteen follow-up summaries report maximum sampled
D/C++ checksum differences of zero for float and double. The shared-coefficient
C++ code is a performance comparator, not an independent scientific oracle.

The workload and flags follow the
[baseline methodology](R7_4_5_PERFORMANCE_BASELINE.md): 65536 items, three
warm-ups, nine rounds of sixteen batches in each order, 18 samples per case,
28 cases per variant/language. Variant order reverses on the second pass;
each D executable has fresh paired C++ timings on the same allowed CPU.
Lookup severity indices shift per batch; lookup+apply traverses i%1001/1000.
Allocations and full component validation are untimed. Validation cache effects
relative to C++ warm-up remain a measurement limitation.

DMD: -O -inline -release -boundscheck=on.
LDC: -O3 -fp-contract=off -release -boundscheck=on.
GCC: -std=c++17 -O3 -ffp-contract=off -fno-fast-math.
Frequency, turbo, thermals, SMT and shared-host load are uncontrolled.

Across all deficiencies in the follow-up, fixed pure lookup takes 84–85% of
the Slice float time and 91–92% of double time under LDC 1.41.0.
For LDC 1.43.0, it takes 66–69% for float and 77–78% for double.
Residual fixed/C++ pure-lookup ratios are about 1.18/1.22 with LDC 1.41.0 and
1.03/1.11–1.12 with 1.43.0. The initial run also shows fixed-table LDC gains,
but these two runs have different binaries/runner placements and are not
controlled fixed-binary replications.

DMD 2.111.0 reproduces the fixed float regression: protan pure lookup rises
from 29.223 to 158.866 ns and lookup+apply from 42.241 to 174.576 ns.
The bounded index brings these to 29.368 and 44.666 ns respectively.
It removes most of the new penalty rather than closing the original C++ gap.
DMD 2.113.0 does not show that fivefold fixed-table penalty.

Direct interpolation improves DMD double pure lookup (protan roughly 46.6 to
30.4 ns) while making LDC pure lookup slower. Bounded int indices also slow
LDC pure lookup, but improve the combined LDC float workload in this sequence.
Lookup-only winners therefore cannot be selected for combined application
without measuring it separately.

Follow-up LDC 1.43.0 and both DMD jobs used EPYC 7763; LDC 1.41.0 used EPYC
9V74. The initial run has different CPU assignments recorded in its metadata.
Do not rank compiler versions by absolute ns/item or accept small differences
as controlled-machine evidence.

## Generated code and decision

In LDC 1.43.0, the Slice lookup loop calls matrixAtSeverity per item; the fixed
and direct lookup loops contain no such per-item helper call.
Fixed float interpolation shows packed arithmetic; direct float interpolation
shows scalar arithmetic in the inspected loop. Direct stores do not universally
improve floating-point kernels.

For DMD 2.111.0, fixed float lookup retains a helper with x87 conversion/control
word instructions for the unsigned size_t conversion. The bounded version uses
cvttss2si and removes those x87 control-word instructions. The large runtime
difference and focused source change support this index-conversion hypothesis;
they are not a complete causal model or a demonstrated general compiler defect.
Function calls, aggregate copies, checks and code placement remain relevant.

**Decision:** retain the fixed representation, bounded-index and direct forms
as research evidence; reject a universal replacement based on these runs.
LDC fixed-table lookup gains are useful, but compiler/scalar/operation trade-offs
remain. No compiler-specific production fork is introduced or accepted here.

The production performance gate remains open. A controlled consumer-machine
replay of the promising forms, with representative batch sizes and both lookup
workloads, should precede choosing an internal implementation policy.
Residual Viénot float and DMD C++ gaps, independent numerical reference
qualification, consumer composition and API review remain separate work.
